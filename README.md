# Сайт мережі ломбардів «Імперіал»

Next.js 16 + Payload CMS 3. Сайт і адмінпанель — один застосунок.

---

## Кому що потрібно

**Наповнюєте сайт даними** — тарифи, відділення, акції, тексти?
Вам потрібна тільки **адмінка**, код чіпати не треба. Заходьте за адресою сайту `/admin`.

**Правите код?** Далі — про це.

---

## Запуск на своєму комп'ютері

```bash
npm install
cp .env.example .env      # за потреби впишіть свої значення
npm run build && npm start
```

Відкрити: http://localhost:3000/admin

Перший запуск створить порожню базу — файл `imperial.db` поруч із проєктом.
Нічого встановлювати не потрібно: ані PostgreSQL, ані Docker.

### Наповнити базу початковими даними

```bash
node scripts/seed.mjs http://localhost:3000 admin@example.com ВашПароль
```

Завантажить 10 тарифів, 4 ставки, 4 статуси лояльності, 26 відділень Дніпра
й загальні налаштування. Скрипт можна запускати повторно — він оновлює наявне,
а не створює дублікати.

### Два режими

| Команда | Для чого | Швидкість адмінки |
|---|---|---|
| `npm start` | робота з даними | сторінки за 0,02 с |
| `npm run dev` | розробка з автооновленням | сторінки за 15 с – 4 хв |

`npm run dev` повільний, бо збирає інтерфейс наново на кожному заході.
Для наповнення даними завжди `npm start`. Після зміни коду — `npm run build && npm start`.

## Структура

```
app/(frontend)/     публічний сайт
app/(payload)/      адмінка та API
collections/        моделі даних
lib/                розбір файлу прайсу
components/         кнопка завантаження прайсу в адмінці
scripts/            наповнення бази
```

**Важливо:** сайт і адмінка розділені на дві групи маршрутів. Якщо їх звести
в один layout, стилі глобального CSS переб'ють стилі Payload і адмінка
відрендериться напівголою.

## Оновлення прайсу

Розділ **«Оцінка → Тарифи за грам»**, кнопка **«Завантажити прайс»**.

З файла беруться **лише дві колонки** — скупка та базова ціна. Ціни за статусами
в прайсі теж є, але не імпортуються: вони рахуються з надбавок у розділі
«Програма лояльності». Перевірено на прайсі 24.08.2026 — формула збіглася
на всіх 28 значеннях.

За сріблом колонки скупки немає, тому скупка дорівнює базовій ціні.
Усі ціни зберігаються цілими гривнями.

## База даних

Обирається автоматично за оточенням:

- є `DATABASE_URL` або `NETLIFY_DATABASE_URL` → **PostgreSQL**
- немає → локальний файл **SQLite**

**Пастка при зміні полів.** SQLite оновлює структуру тільки в режимі `npm run dev`
і питає підтвердження прямо в терміналі — процес чекатиме відповіді й запити
висітимуть. Якщо після правки моделі бачите помилку `no such column`,
запустіть `npm run dev`, дайте відповідь на питання, потім поверніться на `npm start`.

## Розгортання

Гілка `main` збирається автоматично. Інші гілки отримують окрему адресу
для перевірки — робочий сайт при цьому не зачіпається.

Змінні оточення на сервері:

| Змінна | Навіщо |
|---|---|
| `PAYLOAD_SECRET` | ключ шифрування сесій, довгий і випадковий |
| `DATABASE_URL` | рядок підключення до PostgreSQL |
| `NEXT_PUBLIC_SERVER_URL` | адреса сайту |

**Файлова система на serverless тимчасова.** Тому база має бути зовнішньою,
а завантажені зображення — у хмарному сховищі, інакше вони зникнуть
після першого ж перезапуску.
